# Stage 8 — 运营洞察与接入稳定化（v1.3）

> 状态：proposed（待项目负责人确认排期）｜ 前置：S1~S7（已完成，v1.2.0 已发布）｜ 里程碑：M7 ｜ 粗估：13 人日

## 背景（v1.2.0 进展审核结论）

v1.2.0 已发布：P0 需求 F-001~F-012 全部落地，CI 7 job 全绿，GoldenSet 验收 PASS
（Recall/事实支持/不可答准确率均 1.00，P0 安全违规 0），发版流水线与分支保护生效。
对照本阶段（接入稳定性、状态监测、成功率与时延统计、余额监测、查询 API、单页展示）
审核发现 4 项差距：

1. **统计面只有 Prometheus**（F-006）：宿主必须自建抓取链路才能看到数据；进程内
   无"最近 1 小时成功率 / p95 时延"这类可直查聚合——本机快速排障需要零依赖直查。
2. **无余额/配额监测**：Jev 是唯一计费依赖（决策 provider），余额完全不可见；
   余额耗尽会表现为整链降级，难以定位。O-2 协议未定，可按 5.2 同策略 fake 先行。
3. **无诊断查询面**：Health() 是编程接口；无可直接打开的 API/页面快速查看
   运行状态、统计、余额。
4. **稳定性薄弱点**：
   - `deadline.Call` 不 recover provider panic——任何 EvidenceProvider/DecisionProvider
     panic 将击穿宿主进程（全库唯一 recover 在事件总线订阅者隔离，bus.go）；
   - Jev 无熔断：故障期间每个请求都烧完整 rejudge 超时预算后才降级（慢失败）；
   - Health() 每次调用全量探测（宿主控制频率，符合设计；但仪表盘高频轮询需要短 TTL 缓存）。

## 目标

在**保持 SDK 形态**（可选组件、默认零侵入）前提下交付：

1. 进程内运行统计：问答请求成功率、时延分位（p50/p95/p99）、阶段耗时、缓存命中、
   降级路由的滚动窗口聚合与查询（F-015）。
2. 余额监测：BalanceSource 契约 + Jev 适配（O-2 fake 先行）+ 四态判定 + 阈值事件（F-016）。
3. 诊断查询 API：可选本机 HTTP 服务（JSON），一次性拉全或分面查询（F-017）。
4. 单页仪表盘：内嵌单文件 SPA，本机打开即看状态/统计/余额趋势（F-018）。
5. 接入稳定化：provider panic 隔离、Jev 熔断器（F-019）。

## 范围内 / 范围外

**范围内**：internal/stats 滚动窗口聚合器（订阅既有事件总线）；internal/balance 契约
与轮询；internal/diag 可选 HTTP 服务（Option 启用）；internal/diag 内嵌 SPA（embed）；
deadline.Call panic 隔离；Jev 熔断；契约测试扩展；v1.3.0 发布。

**范围外**：对外服务化包装（F-014 边界不变，见 ADR-0003）；诊断面鉴权/多租户
（本机单用户，无隐私安全要求）；分布式/跨副本聚合；OTel 导出；余额充值等操作类接口；
告警外发通道（只产事件与状态，通知归宿主）。

## 关键口径（预决策，评审可改）

- **成功率定义**：`err == nil` 且 `action ∈ {answer, ask_clarification, abstain}` 记成功
  （abstain/clarify 是正确行为而非失败）；`Degraded` 单独成列不折算成功率；
  `invalid_request/deadline_exceeded/error` 记失败并按 outcome 分类。
- **时延分位**：固定对数桶直方图（1ms~10s，约 30 桶 + 溢出桶），内存有界恒定；
  分位为桶内线性插值（误差上界 = 桶宽/2，注释化）。窗口 1m/5m/15m/1h 环形桶（桶宽 5s）。
- **诊断面边界**：`WithDiagnosticServer(addr)` Option，默认**不启用**；启用后默认绑定
  `127.0.0.1`，无鉴权（本机用途，ADR-0003）；与 F-014 服务化互不相关。
- **余额口径**：`normal（>low）/ low（>critical）/ critical（≤critical）/ unknown（查询失败）`；
  阈值与轮询周期进配置节 `balance:`（低阈值默认为 critical 的 2 倍或显式配置）。
- **熔断口径**：仅 Jev 级；默认开启；连续失败 N=5 进 open（直接走降级链，不发起调用），
  冷却 30s 后半开单探测；状态进 Health detail、stats 与仪表盘。

## 风险与注意事项

- O-2 余额端点协议未定 → fake 先行（与 5.2 同策略）；协议到位仅改 internal/balance 的 Jev adapter。
- diag HTTP 有"SDK 起服务"观感 → ADR-0003 固化边界：可选工具组件、默认关闭、仅本机；
  F-014（对外服务化）仍留 post-MVP。
- SPA 禁用构建链与 CDN → 单 HTML 文件 + vanilla JS + 内联 SVG 图，复杂度上限受控；
  图表手写（折线/条形即可），不引第三方库。
